# Architecture

Structure, data flow, module responsibilities, and delivery pipeline for the Designated Emergency Evacuation Site Map.

See [specification.md](./specification.md) for features, screens, and data specifications.

## Overview

```text
┌──────────────────────────────────────────────────────────────┐
│ Cloudflare Workers (static asset delivery)                    │
│ build/client + public/assets/*.geojson.gz                     │
└────────────────────────────┬─────────────────────────────────┘
                             │ fetch (.geojson.gz)
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ Browser SPA (React Router / Vite, ssr: false)                  │
│                                                              │
│ Home (routes/home.tsx) ── filters, mobile view tab           │
│   └─ useShelterMap  ──► filters + viewport sync + selection    │
│          ├─ useShelterData ──► fetchShelters → Shelter[]       │
│          ├─ useLeafletMap  ──► Leaflet Map + tiles             │
│          ├─ useCurrentLocation ──► Geolocation + marker        │
│          │                                                   │
│          ├─ displayedShelters ──► MapTable (virtualized list)  │
│          ├─ visibleShelters ──► Leaflet layers / MapTable      │
│          └─ selectedShelterId ◄──► table rows / popups         │
└──────────────────────────────────────────────────────────────┘
```

There is no backend API or database. Evacuation site data is delivered as static files alongside the build output; the client decompresses, validates, and renders it.

## Runtime data flow

### 1. Startup and data loading

```text
Home
  └─ useShelterMap
       └─ useShelterData
            └─ fetchShelters()
                 ├─ publicUrl('assets/mergeFromCity_2.geojson.gz')
                 ├─ decompressGzipResponse (decompress gzip if needed)
                 ├─ JSON.parse
                 └─ parseShelterGeoJson → Shelter[]
```

- `fetchShelters` caches the result at module scope
- It also handles hosts that return an already decompressed body (gzip is detected using the magic bytes `1f 8b`)
- Loading state reaches the UI through `Home` as `isLoading` / `loadError`

### 2. Shared filters

```text
ShelterFilterBar
  filters (Home state, immediate)
       │ keyword: 200ms debounce (useDebouncedValue); chips and checkboxes: immediate
       ▼
  appliedFilters ──► useShelterMap(mapContainerRef, appliedFilters)
       ▼
  filterShelters(shelters, appliedFilters)
       ▼
  displayedShelters ──┬──► MapTable (all results, virtual scrolling)
                      └──► filterSheltersWithinMap ──► visibleShelters
                                 ├──► syncShelterLayers (map)
                                 └──► MapTable when "地図の表示範囲のみ" is on
```

The table displays all filtered results by default, while the map creates layers only for results within the current viewport. When the map is hidden (the list tab on phones) it has no size, so the last viewport is kept.

### 3. Selection between the table and the map

```text
row click ──► focusShelter ──► map.flyTo ──► moveend ──► openPopup (pending id)
popupopen on a shelter layer (feature group) ──► selectedShelterId ──► row highlight + scroll
popupclose on the map ──► clear selectedShelterId
```

The layer whose popup is open is kept during viewport synchronization even when the popup's auto-pan moves it out of view, because removing the layer would close the popup.

### 4. Map layer synchronization

On `moveend` / `zoomlevelschange`, the app:

1. Extracts evacuation sites within the viewport using `map.getBounds()`
1. Chooses pins or circle markers based on zoom and result count, and a style (default or match, with the match color) based on the selected disaster types
1. Uses `ShelterLayerRegistry` to apply only additions, removals, and changes in layer type, style, or color, and resizes existing circles when the zoom changes their scale

## Module responsibilities

### Hooks

| Module | Responsibility |
| --- | --- |
| `useShelterMap` | Integrate data, filters, viewport synchronization, selection, and the current location |
| `useShelterData` | Manage the GeoJSON loading lifecycle |
| `useLeafletMap` | Initialize Leaflet, switch tiles, and handle resizing |
| `useCurrentLocation` | Read the Geolocation API, draw the current location, and report errors |
| `useDebouncedValue` | Delay keyword updates |
| `useMediaQuery` | Switch layouts at the `sm` and `lg` breakpoints |
| `useMapControlContainer` | Add an empty Leaflet control for React to portal into (the current location button) |

### Data / Types

| Module | Responsibility |
| --- | --- |
| `fetch-shelters` | Fetch, decompress, parse, and cache assets |
| `types/shelter` | Convert GeoJSON to `Shelter` and validate it |
| `types/shelter-type` | Define disaster type keys, Japanese labels, and colors |
| `types/shelter-filters` | Define the filter state, keyword and disaster type matching |
| `types/tile-layer` | Define tile layers and defaults |
| `generated/dataset-meta` | Provide the data update date displayed in the UI |
| `lib/dataset` | The source URL and the dataset attribution shown on the map |

### Map helpers (`app/lib/map/`)

| Module | Responsibility |
| --- | --- |
| `constants` | Initial view, marker styles, zoom-dependent circle size, and marker thresholds |
| `viewport-filter` | Filter by bounds |
| `shelter-renderer` | Layer registry and incremental synchronization |
| `shelter-popup` | Popup HTML (including escaping) and the directions link |
| `fly-options` | Map flight options: a fixed short duration, or no animation for reduced motion |

### UI Components

| Area | Main components |
| --- | --- |
| filter | `ShelterFilterBar` |
| layout | `AppShell`, `AppHeader`, `ViewTabs` |
| map | `MapTileLayerControl`, `MapHelpHint`, `CurrentLocationButton`, `ListPanelToggle`, `MapAlert`, loading overlay |
| table | `MapTable`, header, rows |

`routes/home.tsx` owns the map container ref, the filter state, the mobile view tab, and whether the list beside the map is collapsed, calls `useShelterMap`, and passes its state to the map and table as props.

## Routing and build

- `react-router.config.ts`: `ssr: false`
- Production `basename` / Vite `base` uses the `BASE_PATH` environment variable (defaults to `/`; leave it unset for Workers, which serves at the root)
- Always reference static assets using `publicUrl()` (through `import.meta.env.BASE_URL`)
- Do not use root-absolute paths such as `/favicon.svg`
- `pnpm run build` runs `scripts/generate-sw.mjs` after `react-router build`, which uses `workbox-build` to write `build/client/sw.js`. It precaches every file in `build/client` (including the GeoJSON) and adds runtime caches for OSM and GSI tiles. See [Offline support](./specification.md#offline-support)
- `app/lib/register-service-worker.ts` registers `sw.js` from `App` in `root.tsx` in production builds only
- After changing `public/favicon.svg`, run `node scripts/generate-icons.mjs` (renders with Playwright and Google Chrome) and commit the PNGs in `public/icons/`

## Data update pipeline

Runs on the first day of each month at 00:00 UTC (09:00 JST), or manually through `workflow_dispatch`.

```text
GSI GeoJSON
  → fetch with curl + validate JSON
  → gzip compression → public/assets/mergeFromCity_2.geojson.gz
  → generate app/generated/dataset-meta.ts from Last-Modified
  → create-pull-request (branch: automated/update-geojson)
```

Related files:

- [`.github/workflows/shelter-map-update-geojson.yml`](../../../.github/workflows/shelter-map-update-geojson.yml)
- [`scripts/write-dataset-meta.mjs`](../scripts/write-dataset-meta.mjs)

## CI / CD

```text
PR / push to main
  ├─ repo - Pre-commit (entire repository)
  │    └─ pre-commit run --all-files (including Biome lint and formatting)
  └─ shelter-map - Test (only for changes under apps/shelter-map/)
       ├─ pnpm run typecheck
       ├─ pnpm run test
       └─ pnpm run test:e2e (separate job; uploads the Playwright report on failure)

PR opened / updated / closed (only for changes under apps/shelter-map/, not from forks)
  └─ shelter-map - Preview
       ├─ pnpm run build
       ├─ wrangler preview --name pr-<number> (creates or updates the Preview)
       ├─ Comment the Preview URL on the PR (one comment, updated on each push)
       └─ wrangler preview delete (when the PR is closed)

push to main (only for changes under apps/shelter-map/) / manual run
  └─ shelter-map - Deploy
       ├─ pnpm run build
       └─ pnpm run deploy (wrangler deploy publishes build/client to Workers)
```

The E2E job builds the app and serves `build/client/` with `wrangler dev`, then runs Playwright with the runner's preinstalled Google Chrome. Map tiles are stubbed so tests never reach OpenStreetMap or GSI, and most scenarios replace the GeoJSON with a small fixture so assertions do not depend on the monthly data update. They cover what unit tests cannot: gzip delivery and decoding through Workers, SPA fallback for unknown paths, filters reflected in both the table and the map, marker colors, selection between the table and the map, the current location (with a mocked position and with permission denied), popups (including HTML escaping and the directions link), tile switching, modifier-key zoom, and the side-by-side layout and its collapsible list, the sticky table header at tablet width, and the mobile tabs and card list. Service Workers are blocked except in `pwa.spec.ts`, which checks the manifest and reloading offline with the precached data.

Test and Deploy run independently, as in tsudou. Deploy runs only on pushes to `main` and manual runs, so pull requests (including those from forks) never reach it. The Cloudflare secrets are passed only to the deploy step, not to dependency installation or the build. Navigation to unknown paths returns `index.html` (`not_found_handling: single-page-application`).

Preview serves each PR at `https://pr-<number>-shelter-map.<subdomain>.workers.dev/` using [Workers Previews](https://developers.cloudflare.com/workers/previews/). The production `workers.dev` URL stays disabled (`workers_dev: false`), while Preview URLs are enabled separately (`preview_urls: true`) and served with an `X-Robots-Tag: noindex` header. `preview_urls` takes effect on the next `wrangler deploy`, so Previews work only after that setting reaches production. Pull requests from forks cannot read the Cloudflare secrets, so Preview skips them.

## Design considerations

1. **Single source of state** — Pass filtered results from `useShelterMap` to keep the map and table consistent
1. **Reduced rendering cost** — Render only the map viewport, use canvas circle markers at low zoom, and update layers incrementally
1. **Large result sets** — Use virtual scrolling to handle all rows in the table
1. **Simple delivery** — Serve a static SPA and gzip assets on Cloudflare Workers without an API or Worker script
1. **Works offline** — Precache the app and data so evacuation sites can be found with a weak or no connection during a disaster
1. **Data safety** — Validate GeoJSON at runtime, skip invalid Features, and fail only when the collection itself is invalid
