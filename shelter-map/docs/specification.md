# 仕様

国土地理院（GSI）の指定緊急避難場所データを、地図とテーブルで閲覧する Web アプリケーションの仕様です。

**デモ:** <https://iwstkhr.github.io/shelter-map/>

## 概要

- クライアントサイドのみの SPA（サーバー API なし）
- 避難場所 GeoJSON は静的アセットとして配信し、ブラウザーで展開・検証
- 地図と一覧は同じ絞り込み状態を共有する

## 機能一覧

| 機能 | 説明 |
| --- | --- |
| 地図表示 | 表示範囲内の避難場所を Leaflet で描画 |
| 一覧表示 | 絞り込み後の全件を仮想スクロール付きテーブルで表示 |
| 絞り込み | 名称・住所・災害種別で地図と一覧を同時に絞り込み |
| タイル切替 | OpenStreetMap / 国土地理院航空写真 |
| データ読込 | gzip 圧縮 GeoJSON の取得・展開・検証 |
| 読込表示 | 読込中は地図上にスピナー、失敗時はエラーメッセージ |
| レスポンシブ | モバイル幅でも地図と一覧が使えるレイアウト |

## 画面構成

```text
┌─────────────────────────────────────────┐
│ ヘッダー（タイトル / GitHub リンク）      │
├─────────────────────────────────────────┤
│ 地図（タイル切替・操作ヒント・読込表示） │  flex 5
├─────────────────────────────────────────┤
│ データ出典・件数                         │
│ テーブル（列フィルター・仮想スクロール） │  flex 4
└─────────────────────────────────────────┘
```

- ルートは 1 ページのみ（`/`）
- 全体は `h-svh` の縦レイアウトで、地図と一覧が画面内に収まる
- 読込エラーは地図上部に赤文字で表示する

### ヘッダー

- アプリ名「指定緊急避難場所マップ」とファビコン
- GitHub リポジトリへの外部リンク

### 地図

- 初期中心: おおよそ関東（緯度 35.4122、経度 139.413）
- 初期ズーム: 8
- ズーム範囲: 5〜18
- 既定タイル: OpenStreetMap

#### 操作

| 操作 | デスクトップ | モバイル |
| --- | --- | --- |
| ズーム | Ctrl/⌘ + ホイール | ピンチ |
| 移動 | ドラッグ | ドラッグ |
| 詳細表示 | クリック | タップ |

通常のホイールだけではズームしない（ページスクロールとの干渉防止）。

#### マーカー描画

表示範囲内の避難場所だけを描画する。

| 条件 | 描画 |
| --- | --- |
| ズーム ≥ 15、または表示件数が 100 件以下 | ピン（marker） |
| 上記以外 | 小さな円（circle） |

移動・ズーム終了時にレイヤーを差分同期する（不要な再生成を避ける）。

#### ポップアップ

クリック/タップで表示する内容:

- 施設・場所名
- 住所
- 各災害種別の指定有無（指定あり / なしのスタイル付き表示）

データ由来の文字列は HTML エスケープしてから差し込む。

### テーブル

| 列 | 内容 |
| --- | --- |
| 名称 | 施設・場所名 |
| 住所 | 住所 |
| 災害種別 × 8 | 指定あり ✅ / 指定なし ❌ |

- 絞り込み後の件数を右上に表示
- 出典リンクとデータ更新日（`DATASET_UPDATED_AT`）を表示
- TanStack Virtual による仮想スクロール
- 横スクロール可能な最小幅（おおよそ 58rem）

## フィルター仕様

地図と一覧は同一の列フィルターを共有する。入力は 200ms デバウンス後に反映する。

### テキスト列（名称・住所）

- 部分一致（`includes`）
- 前後の空白は trim してから比較
- 空文字のときはその列で絞り込まない

### 災害種別列

各災害種別について次のいずれか:

| 値 | 意味 |
| --- | --- |
| `all` | 絞り込まない（既定） |
| `yes` | その災害で指定ありの避難場所のみ |
| `no` | その災害で指定なしの避難場所のみ |

複数の災害種別フィルターは AND 条件で適用する。

## データモデル

### ドメイン型 `Shelter`

```ts
interface Shelter {
  id: string; // 共通ID
  name: string; // 施設・場所名
  address: string; // 住所
  type: ShelterType; // 災害種別ごとの指定有無
  latitude: number;
  longitude: number;
}
```

### 災害種別

| キー | GeoJSON プロパティ名 | テーブル短縮ラベル |
| --- | --- | --- |
| `flood` | 洪水 | 洪水 |
| `landslide` | 崖崩れ、土石流及び地滑り | 崖崩れ |
| `storm_surge` | 高潮 | 高潮 |
| `earthquake` | 地震 | 地震 |
| `tsunami` | 津波 | 津波 |
| `big_fire` | 大規模な火事 | 火事 |
| `flood_within_levee` | 内水氾濫 | 内水氾濫 |
| `volcanic_activity` | 火山現象 | 火山現象 |

GeoJSON 上の指定フラグは文字列 `"1"` を指定あり、それ以外を指定なしとみなす。

### ソース GeoJSON

- 形式: `FeatureCollection`（各要素は Point `Feature`）
- リポジトリ内: `public/assets/mergeFromCity_2.geojson.gz`
- 取得元: <https://hinanmap.gsi.go.jp/hinanjocp/defaultFtpData/geoJSON/mergeFromCity_2.geojson>
- 出典ページ: <https://www.gsi.go.jp/bousaichiri/hinanbasho.html>

### 検証・変換ルール

1. ルートが `FeatureCollection` で `features` 配列を持つこと
1. 各 Feature について Point 座標・共通 ID・名称・住所・全災害種別プロパティが妥当であること
1. 妥当な Feature だけを `Shelter` に変換して採用する
1. 不正な Feature は読み飛ばす
1. コレクション自体が不正な場合は読み込みエラーとする

## タイルレイヤー

| キー | 表示名 | 提供元 |

| `osm` | OpenStreetMap | OpenStreetMap |

## 非機能要件

| 項目 | 内容 |
| --- | --- |
| ランタイム | モダンブラウザー（`DecompressionStream` 利用） |
| 配信 | GitHub Pages（ベースパス `/shelter-map/`） |
| データ更新 | 毎月 1 日に Actions が PR を作成 |
| 品質ゲート | pre-commit、Biome、TypeScript、Vitest |

## スコープ外

現時点で次は対象外とする。

- ユーザー認証・個人データの保存
- サーバーサイド API / データベース
- オフライン対応（Service Worker 等）
- 経路案内・現在地からの距離計算
- 避難所（指定緊急避難場所以外）データの統合表示
